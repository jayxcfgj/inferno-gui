Ich möchte die Alternative zur Dante virtueal Soundcard "inferno" benutzerfreundlicher machen, indem wir ein installationsskript und eine gui für inferno bauen werden. Für ersteres soll ein shell skript für installation, einrichtung und konfiguration erstellt werden, welches alle natwendigen Schritte möglichst autonom abarbeitetet und nur da wo es nötig ist dem user gezielt Fragen stellt die dann beantwortet, um die einrichtung so umszusetzen, wie er es benötigt, bzw. es für sein system notwendig ist. 
Dafür liegt die datei "how to install inferno_final_entwurf.txt" die den groben ablauf des skripts im wesentlichen beinhaltet. es einige kommentare enthalten, welcher schritt /befehl was warum macht....das brauchen wir vielleicht nicht alles so ausführlich im skript, aber die einzelnen schritte sollten schon beim skriptabarbeiten dem usr kurz angezeigt werden. einige nontroll-befehle sind vielleicht auch nicht zwingend erfoderlich, aber eine gute möglichkeit, um zu testen, ob der jewweilige schritt erfolgreich war. baue daraus das skript . es soll am ende die befehle so wie sie da drin stehen ausführen. An stellen wo der user angaben machen soll, soll ihm gezielt die frage gestellt werden und nach möglichkeit die zur auswahl stehenden optionen (beispielsweise welches interface verwendet werdn soll, kann mit einer zu vorangegangenen auflistung der aktuell am system verfügbaren nics aufeglistet werden) die entscheidung möglichst einfach gemacht werden. das skript soill in englisch gehalten sein. 

Das testen direkte testen auf dem aktuellen system kann nicht 1:1 stattfinden, da teilweise diverse installationen vorgenommen werden die das system verändern würden...evtl. müssten solche kritischen befehle beim testen ersetzt werden durch platzhalter o.ä.


Der zweite Schritt ist die Erstellung einer gui für die inferno software. nachdem visuellen und konzeptionellen Vorbild des projektes Sync67 ( gibhub: https://github.com/jayxcfgj/sync67). schaue dir dazu das repo, die agents.md etc. ganz genau an.
Das Aussehen, die verwendeten Werkzeuge, also die Wahl des gui desings, farben, layout aber auch die konzeptionelle umsetzung (also z.B. das strikte trennen von gui und funktion...) soll hier ich gleicher art und Wiese übernommen werden. Es soll am ende eine Gui für inferno entstehen, die man für die alltägliche Nutzung bedient. Die Gui soll, einen start und Stop Button enthalten, um PTP und die Node-erstlungen innerhalb Pipewires zu ermöglichen. Dies soll ein Klick auf den Start Button ermöglichen. Das terminieren dieser nodes innerhalb pipewires (und damit auch das beenden des inferno alsa-pcm-plugins) und der anschließenden benndigung des ptp-prozesses (statime) soll der stopp button erledigen. 
Desweiteren soll der user über die gui die Möglichkeit haben die wichtigsten Einstellungen auf einem Blick einsehen zu können und nach Bedarf verändern zu können. Dazu zählt, Die Wahl des netzwerk-interfaceses mithilfe einer simplen drop down liste, die die aktuell verfügbaren interfaces auflistet und die aktuelle ip-adresse dieses gewählten netzwerks, DIe Anzahl der Audio kanäle, die latenz (bei dieser option bin ich mir nicht sicher, ob inferno dahingehend eine möglichkeit bietet da etwas einzustellen, das müsste recherchiert werden). Desweiterern wäre es ein Radiobutton gut, wo der user auswählen kann, ob ptpv1 oder ptpv2 für die clock benutzt werden soll. je nachdem welche auswhal getroffen wird vom user, muss die entsprechende toml-datei beim statime-startbefehl verwendet werden. Die auswahl der netzwerkschnittstelle muss entsprechend an allen relevanten stellen in den verschiednenen konfigurationsdateienen berücksichtigt und ggf. angepasst werden. Da die eben aufgezähöten parameter nicht zur laufzeit dynamisch geändert werden können, sollte sobald inferno läuft die ui-elemente ausgegraut werden, sodass visuell klar erkennbar ist, das diese Einstellungen nicht zur Laufzeit verändert werden können. Des Weiteren möchte ch ein Logfenster für statime haben. ganz nachdem Vorbild wie bei sync67 mit ptp4l. Da die log-asugabe von statime sehr umfangreich, schnel, und schlehc tzu lesen ist, möchte ich, dass sich dafür ein entsprehcender Filter erstellt wird, der die ausgabe entsprechend auf die wesentlichen infeormationenen reduziert. du kannst dich dabei an die ausgabe von ptp4l halten...jede sekunde eine neue log-zeile woe die wichtigsten werte wie offset etc. drinstehen. der filter sollte natürlich keine wichtigen informationen unterschlagen, wie plötzlich auftretende fehler oder warnhinweise, aber es soll die ausgabe des statime-logs übersichtlich und lesbar machen.
Für den maximalen Konfort wäre es schön, wenn ein entprechendes Task-icon implementiert werden könnte, sodass man die gui jederzeit wieder hervorholen kann, wenn man beim arbeiten einen blick draufwerfen möchte, aber man auch das fentster komplett schließen kann, aber die inferno software läuft rtodem weiter im hintergrund bzw. minimiert.

Desweiteren wäre ein button ganz schön, der den webbrowser öffnet und direkt auf die weboberfläche von netaudio öffnet, um im dante netzwerk direkt mit dem routing beginnen zu können.
